# AdmitFlow - Forecast Segment Stability (AF-019)

> **The dataset is synthetic.** Every figure below describes a fit to a simulated
> admissions funnel generated by `scripts/generate_dataset.py`. Nothing here is
> real-world forecast performance and none of it transfers to a real institution.

---

## Objective

To measure whether forecast performance for `cum_enrolled` is **reasonably consistent**
across the meaningful segments that already exist in the forecast dataset, at each
supported horizon. This adds a segment-level view to the existing per-horizon forecast
evaluation; it does not rebuild or retune the forecasting pipeline.

The existing `reports/forecast_results.md` reports per-horizon aggregate error and a
programme table that **pools all four horizons** (section 5). It does not report
error per segment per horizon. That is the gap this analysis fills.

Stability is **measured, not asserted**. No composite "stability score" is
invented, and the model is not labelled stable or unstable. Where observed variation
falls inside the noise implied by the cell sizes, that is reported as *not
distinguishable from sampling variation*, which is a different and more defensible
claim.

## Segment definitions

Only fields genuinely present in `forecast_features.csv` are used. They fall into two
classes, and each class is verified by the check that actually applies to it.

**Class (a) static `dim_programme` attributes.** `programme_id`,
`selectivity_tier`, `campus_region_id`, `faculty`. Each holds one value per programme,
so pre-origin availability is proven by checking it never changes across all 4 cycles
and all 12 eligible origins. Verified for all four fields.

**Class (b) funnel state at the origin.** `has_enrolments`. This legitimately *varies*
between origins of the same programme - a programme whose first eligible origin (week
25) still has no enrolment history has `has_enrolments = 0` there and 1 later. A
time-invariance test is the wrong test for such a field and would reject a legitimate
one, so a stronger check is used instead: the field is **re-derived from the raw panel
using only weeks at or before the origin** and compared row for row.

- `has_enrolments`: 552 origins, 0 mismatches - fully reconstructible from pre-origin weeks

### `programme_id` - programme

- **Meaning**: programme
- **Levels**: 12 in the full artifact
- **Test rows per level**: 44 to 44 total across all four horizons (11 to 11 per horizon)
- **Class**: static dimension
- **Pre-origin availability**: verified time-invariant per programme
- **Why relevant**: the primary operational unit. A yield plan is written per
  programme, so per-programme forecast reliability is the question an
  admissions team actually asks.

### `selectivity_tier` - selectivity tier

- **Meaning**: selectivity tier
- **Levels**: 3 in the full artifact
- **Test rows per level**: 132 to 220 total across all four horizons (33 to 55 per horizon)
- **Class**: static dimension
- **Pre-origin availability**: verified time-invariant per programme
- **Why relevant**: groups programmes by how competitive they are. Tests
  whether the model is systematically weaker on highly selective programmes,
  which have fewer admitted applicants per unit of enrolment.

### `campus_region_id` - campus region

- **Meaning**: campus region
- **Levels**: 4 in the full artifact
- **Test rows per level**: 44 to 220 total across all four horizons (11 to 55 per horizon)
- **Class**: static dimension
- **Pre-origin availability**: verified time-invariant per programme
- **Why relevant**: operational grouping. Tests whether forecast reliability is
  concentrated geographically.

### `faculty` - faculty

- **Meaning**: faculty
- **Levels**: 5 in the full artifact
- **Test rows per level**: 44 to 220 total across all four horizons (11 to 55 per horizon)
- **Class**: static dimension
- **Pre-origin availability**: verified time-invariant per programme
- **Why relevant**: organisational grouping, a different cut from region. If
  weakness clustered by faculty but not by region, that would point at
  programme mix rather than any single cause.

### `has_enrolments` - enrolments recorded at or before origin (0/1)

- **Meaning**: enrolments recorded at or before origin (0/1)
- **Levels**: 2 in the full artifact
- **Test rows per level**: 8 to 520 total across all four horizons (2 to 130 per horizon)
- **Class**: origin state
- **Pre-origin availability**: verified reconstructible from panel weeks <= origin
- **Why relevant**: funnel state **at the origin**, not an outcome. Tests
  whether the model is less accurate for origins that have no enrolment history
  yet. It is verified reconstructible from panel weeks at or before the origin,
  so using it introduces no future information. As the counts below show, the
  data cannot support a conclusion on this field.

### Fields deliberately not used as segments

| Field | Reason |
|---|---|
| `cycle_id` | perfectly collinear with split_hint (CYC-2025 is the whole test split) |
| `award_level` | single level 'UG' - no variation to measure |
| `split_hint` | is the train/validation/test boundary, not a segment |

`cycle_id` deserves emphasis because it looks like the most natural segment dimension
and is **not usable**. The split map is:

| Cycle | Splits it appears in |
|---|---|
| `CYC-2022` | train |
| `CYC-2023` | train |
| `CYC-2024` | validation |
| `CYC-2025` | test |

Each cycle belongs to exactly one split, so `cycle_id` and `split_hint` are perfectly
collinear. Segment performance *by cycle* on the test split would be one level of 132
rows - that is, the aggregate restated. Reporting it as a segment would manufacture the
appearance of a cycle-level stability finding. It is stated as a structural limitation
instead.

## Segment sample sizes

Minimum cell size for reliable interpretation: **n >= 30**.

This is the threshold already used for programme-level error in
`reports/forecast_results.md` section 5, so the two documents agree on what
"reportable" means. It is not arbitrary. On the test split the absolute error has a
standard deviation of 5.62 enrolments (mean 5.01), so a 30-observation
cell carries an approximate standard error on segment MAE of 1.03, or about
20% of the mean. Below 30 observations a segment's MAE is
mostly sampling noise and cannot be meaningfully ranked against another segment.

Cells below the threshold are **printed and counted, never silently dropped**.

Per-horizon cell sizes, test split:

| Segment field | Levels | Min cell per horizon | Max cell per horizon | Cells below 30 |
|---|---|---|---|---|
| `programme_id` | 12 | 11 | 11 | 48 of 48 |
| `selectivity_tier` | 3 | 33 | 55 | 0 of 12 |
| `campus_region_id` | 4 | 11 | 55 | 8 of 16 |
| `faculty` | 5 | 11 | 55 | 12 of 20 |
| `has_enrolments` | 2 | 2 | 130 | 4 of 8 |

In total **144 segment-horizon cells fall below n = 30**, out of
208 evaluated across both evaluation splits and all four horizons. These
are marked **INSUFFICIENT** in every table below and are excluded from the dispersion
summaries, which would otherwise be dominated by sampling noise.

### Row count is not independence

A second, separate sufficiency problem survives the n >= 30 threshold.
`campus_region_id`,
`faculty` and `selectivity_tier` are all partitions of `programme_id`, so every level
of them is really a set of programmes. A level holding 44 rows but only **one**
programme carries no more independent information than that programme itself. Those
levels are marked `SINGLE PROGRAMME` in the tables and must not be read as
replicated segment evidence.

| Field | Level | Programmes inside | Interpretation |
|---|---|---|---|
| `selectivity_tier` | `emerging` | 5 | pool of 5 programmes |
| `selectivity_tier` | `medium` | 4 | pool of 4 programmes |
| `selectivity_tier` | `high` | 3 | pool of 3 programmes |
| `campus_region_id` | `REG-01` | 5 | pool of 5 programmes |
| `campus_region_id` | `REG-02` | 4 | pool of 4 programmes |
| `campus_region_id` | `REG-03` | 2 | pool of 2 programmes |
| `campus_region_id` | `REG-05` | 1 | relabelled single programme, not independent evidence |
| `faculty` | `Faculty of Science` | 5 | pool of 5 programmes |
| `faculty` | `Faculty of Technology` | 3 | pool of 3 programmes |
| `faculty` | `Faculty of Commerce` | 2 | pool of 2 programmes |
| `faculty` | `Faculty of Humanities` | 1 | relabelled single programme, not independent evidence |
| `faculty` | `Faculty of Management` | 1 | relabelled single programme, not independent evidence |

**3 levels across 2 of the coarse dimensions contain a single**
**programme**, so they are relabelled programmes rather than segments in their own
right. Every such level is flagged `SINGLE PROGRAMME` in the tables below.

`has_enrolments` is deliberately absent from this table because it is not a
partition of programme. It splits *origins*, not programmes, so both of its levels
contain all 12 programmes and the programme count says nothing about how the cell is
balanced. Its problem is the opposite one - imbalance in rows, not in independent
units.

**The central structural fact of this analysis:** a programme-horizon cell holds only
**11 test observations** (12 programmes x 11 eligible origins / 528 test rows). That is
below the threshold, so **per-programme, per-horizon error is not reliably estimable**
from this dataset. It becomes estimable only when the four horizons are pooled into 44
observations per programme, which is the cut the existing report uses. Both are
reported: the per-horizon table below for completeness, and the pooled table that can
actually be interpreted.

## Metrics by segment

Metrics are the ones the existing forecast evaluation already uses, so results are
directly comparable with `reports/forecast_results.md`:

- **MAE** - mean absolute error, in enrolled applications
- **RMSE** - root mean squared error, penalises large misses more than MAE
- **Bias** - mean signed error; positive means over-prediction
- **Actual / predicted mean** - to expose level bias separately from spread
- **Skill vs persistence** - `1 - MAE_segment / MAE_persistence`, the reference already
  established in the existing report

**Aggregate** is the same horizon, same split, all programmes pooled. It is shown next
to every table so a segment can be compared with the overall result.

## Stability analysis

Dispersion is reported as median, IQR, full range and worst-to-best ratio over
segments **clearing the sufficiency threshold only**. The noise floor is the
approximate standard error a segment MAE carries at its own cell size:
`SE = sd(|error|) / sqrt(n)`, using the test-split error sd of 5.62.

Where the observed range is comparable to the noise floor, the correct statement is
that the segments are **not distinguishable** - not that they are equal, and not that
the model is stable.

### Is variation concentrated in particular programmes?

Two different questions, and they have different answers.

**1. Is the *level* of enrolment concentrated? Yes, strongly.** Programme means of the
target range from 20.5 to 87.8 enrolled, a
4.3x spread. This is a property of programme size, not of forecast
accuracy.

**2. Is the *error* concentrated? Checked directly below.**

Pooled test error by programme (all horizons, n = 44 each, all above threshold):

| Statistic | MAE | RMSE |
|---|---|---|
| Median across programmes | 4.32 | 5.38 |
| Q1 | 3.90 | 4.79 |
| Q3 | 4.80 | 6.55 |
| IQR | 0.90 | 1.75 |
| Min | 2.95 | 3.84 |
| Max | 12.16 | 17.46 |
| Range | 9.20 | 13.61 |
| Worst / best | 4.11x | 4.54x |

**Absolute error is strongly scale-dependent.** Pearson r between programme mean
target and pooled MAE is **+0.840**. The largest programme, `PGM-07`
(mean 87.8 enrolled), carries the largest absolute error
(MAE 12.16). This is not a property of the model alone - the
persistence reference is *more* scale-dependent still (r = +0.970) - so a
raw MAE ranking largely ranks programme size.

**The scale-free view does not support a single weak programme.** Skill against
persistence across the 12 programmes runs +0.193 to +0.758,
a spread of 3.33x on the underlying
MAE/persistence ratio. The programme with the worst absolute MAE, `PGM-07`,
still scores +0.615 on skill - mid-pack, not worst.
The programme with the **worst skill** is `PGM-05` at +0.193, and the reason is the benchmark rather than the
model: its persistence MAE is 5.45, the **lowest of all 12** programmes, so persistence is already near-perfect there and there is little for
   the model to improve on. It is not a programme the model forecasts badly.

The 4.1x MAE spread is also **not a continuum**: excluding `PGM-07`, the
other 11 programmes span 2.95 to 6.70, a 2.3x spread against a
3.5x spread in their size. The observed
programme dispersion is one large outlier plus a tight cluster, so **the median
(4.32) is the more honest summary than the range**.

### Assessment

- `has_enrolments` at H1 has only one segment above the sufficiency threshold, so dispersion cannot be assessed at that level.
- `has_enrolments` at H2 has only one segment above the sufficiency threshold, so dispersion cannot be assessed at that level.

- On the coarse groupings (`selectivity_tier`, `campus_region_id`, `faculty`), some segment differences exceed the sampling noise floor.
- Per-programme, per-horizon error is not estimable (11 observations per cell).

  independent units than their row counts suggest.
- The evidence does not support declaring the model stable or unstable. It supports
  the narrower statement that error varies by programme, that the variation is far
  smaller than the variation in programme size, and that at single-horizon
  granularity the dataset is too small to characterise it.

## Notable deviations and outliers

Actual calculated findings only.

1. **Highest pooled test MAE: `PGM-07`** at 12.16 enrolled (aggregate 5.01, difference +7.15). Its target mean is 87.8 - the largest of the 12 - so this is the biggest programme rather than a pathological one, and its skill against persistence is +0.615, mid-pack.
2. **Lowest pooled test MAE: `PGM-11`** at 2.95 enrolled (difference -2.05 against aggregate); its target mean is 20.5, the smallest of the 12.
3. **The scale-free outlier is a different programme.** `PGM-07` has the worst absolute
   MAE, but the worst *skill* belongs to `PGM-05` at +0.193. Ranking programmes by MAE and by skill give
   different answers.
4. **`PGM-07` swings sign across horizons.** Its per-horizon bias runs H1 +4.11, H2 -3.75, H4 -9.07, H6 -19.29
   (n = 11 each, so each figure is noisy), while its pooled bias is -7.00. The under-prediction deepens with horizon, which is the
   pattern of an enrolment curve maturing after the last observed data point rather
   than a uniform scale offset.
5. **`Faculty of Commerce` is the worst coarse grouping** at 7.70 pooled MAE (+2.70 vs aggregate), but it holds only 2 programmes - PGM-07, PGM-12 - whose pooled MAEs are 12.16 and 3.25. The mean of two
   programmes that far apart is not evidence of a faculty-level effect.
6. **Every programme's *pooled* skill against persistence is positive**, ranging +0.193 to +0.758 over 44 observations each, so no
   programme is forecast worse than simply carrying the last observed value forward.
   Finding 10 shows this does not hold at single-horizon granularity.
7. **Aggregate bias is positive at every horizon in the test split** (H1 +3.29, H2 +0.22, H4 +2.21, H6 +0.36), so
   the model consistently over-predicts cumulative enrolment. The magnitude is not
   monotonic - H2 is near zero while H4 is the largest - which matches the alternating
   bias pattern recorded in `reports/forecast_results.md`. The same sign holds on validation at
   4 of 4 horizons. This is a system-level deviation, not a segment effect.
8. **18 of 22 reportable pooled segment cells show positive bias**
   (21 of 26 if single-programme levels are counted), so
   over-prediction is a system-level property rather than something specific to one
   segment.
9. **No reportable segment had a *worse* MAE than persistence.** The weakest pooled
   skill across every field is +0.193, so even the least
   favourable segment beats the reference.
10. **Negative skill does occur, but only in cells too small to interpret.** 2 programme-horizon
    cells on the test split score below the persistence reference: PGM-05 at H1 (-0.175), PGM-06 at H1 (-0.087).
    All hold n = 11 and are marked INSUFFICIENT. They are reported rather than
    dropped, but no conclusion is drawn from them, and they do not contradict
    finding 9, which concerns pooled cells of n = 44.
11. **`has_enrolments` is effectively degenerate on the test split**: the level with no
   enrolment history holds only 2 observation(s) per horizon and is marked
   INSUFFICIENT at every horizon. The field cannot support a segment conclusion on
   this data, and none is drawn. The cause is the eligible origin window starting at
   week 25: 10 of 12 programmes have at least one origin there with no
   enrolment history, but in the test cycle CYC-2025 only 2 do, and
   each contributes a single origin.
12. **The four largest single-row absolute errors on the test split** are [39.4, 38.5, 38.3, 38.0] enrolled,
    and all of them fall in PGM-07 x4. These are individual row outliers rather than
    a segment pattern in their own right, though they do concentrate in the same
    programme already identified as the largest. With no resampling and 132 rows per
    horizon, no inference is drawn from them.

## Limitations

1. **Per-programme, per-horizon error is not estimable.** A cell holds 11 test
   observations. This is the binding constraint on the whole analysis and no
   statistical treatment can remove it. Per-programme results require pooling
   horizons, which mixes four different difficulty levels.
2. **144 segment-horizon cells fall below n = 30** and are excluded
   from every dispersion figure. They are printed, counted and marked INSUFFICIENT.
3. **Consecutive origins are heavily overlapping.** The panel is one row per
   programme-cycle-week, so the 11 origins of a programme-cycle at a given horizon
   overlap in their underlying history. Their errors are therefore correlated and the
   nominal n overstates the independent information. This is the same reason n = 11
   cannot be treated as 11 independent observations. (The 2,529 applicants holding
   multiple applications are a dependence in the *application* tables and do not
   create rows here, so they are not the binding issue for this analysis.)
4. **A single cycle per evaluation split.** CYC-2024 is the whole validation split and
   CYC-2025 the whole test split. No cycle-level stability can be assessed, and a
   cycle-specific shock would be indistinguishable from a general one.
5. **Dispersion across segments is a maximum-over-segments statistic.** With 2 to 12
   usable segments per field, the observed range is biased upward as a measure of true
   spread, and the bias grows as usable segments get fewer. The IQR and median are
   reported alongside it for that reason, and the range should not be read as a
   population spread.
6. **The noise floor is an approximation.** It uses the pooled test error standard
   deviation and a normal-approximation standard error. Absolute errors are not
   normally distributed, and with n as low as 33 the true sampling spread of a segment
   MAE would be somewhat wider than shown. The comparison is therefore a rough guide,
   not a formal test.
7. **No cross-validation and no repeated evaluation.** A single fit on one train set
   means segment differences cannot be separated from fit-to-fit variation.
8. **Absolute error is scale-dependent.** Programme sizes differ by roughly 4.3x and pooled MAE
   correlates with programme size at r = +0.840, so the programme MAE
   ranking partly ranks programme size. **Skill against persistence** is reported
   alongside it because it is scale-free, and the **within-programme R2** already
   published per horizon in `reports/forecast_results.md` is the appropriate view for
   the opposite question. Segment-level within-programme R2 is not recomputed here
   because it is undefined for the coarse groupings, whose levels pool several
   programmes with different baselines.
9. **Synthetic data.** The dataset is generated by `scripts/generate_dataset.py`. The
   funnel structure, conversion rates and yield maturation are all simulated, so
   these stability figures describe a simulated system and carry no claim about real
   institutional forecasting.
10. **No generalisation beyond this dataset.** Four cycles, 12 programmes, one
    institution, one funnel definition. Nothing here supports a claim about forecast
    stability in general.
11. **Predictions were regenerated, not read from disk.** The artifact stores no
    predictions. Reconciliation against all 8 published aggregates makes this safe,
    but it is a verification of equality, not a byte-level identity of a saved model
    file.

## Reproduction

```
cd admitflow-data
python scripts/build_forecast_features.py   # only if the feature file is absent or stale
python scripts/forecast_segment_stability.py
```

`build_forecast_features.py` is a prerequisite but not part of AF-019: it rebuilds
`data/processed/forecast_features.csv` from `data/raw/fact_forecast_panel.csv` and runs
the leakage guard. If the artifact is already present, AF-019 reads it and does not
rebuild it.

The script is deterministic: it fits the published model with the published seed and
performs no sampling, bootstrapping or iteration. Three consecutive runs produce a
byte-identical report. It does not regenerate the dataset, does not modify
`build_forecast_features.py` or `train_forecast.py`, and does not retune the model.

Exit codes: `0` success, `3` published-metric reconciliation failed, `4` temporal
integrity failed.
