# AdmitFlow - Model Explainability and Error Analysis

> **The dataset is synthetic.** Everything below describes two models fitted to
> simulated admissions data generated by `scripts/generate_dataset.py`. None of it is
> real-world institutional performance and none of it may be reported as such.

Primary target `enrolled_flag`, predicted at `application_submitted_ts`, one row per
application. Error analysis uses the existing chronological **test** split
(CYC-2025, 3,001 rows, base rate 0.262912) at threshold 0.50.

---

## 0. Method and integrity check

Nothing is persisted to disk, so both estimators were refitted with their exact
published configurations and the same seed purely to recover coefficients and
row-level predictions. **No hyper-parameter search, no tuning, no re-fitting for a new
purpose, and no attempt to improve either model.**

To guarantee these are the same two models that were compared, the refit is checked
against every metric already published in `reports/model_comparison.md`. The run
aborts if any value moves:

| Check | Result |
|---|---|
| Published metrics reproduced | **all matched** (log loss, ROC-AUC, PR-AUC, F1 on both splits, both models) |
| Published test confusion cells reproduced | **all matched** (TN, FP, FN, TP, both models) |
| Threshold | 0.5 for both models, unchanged |
| Seed | `20240817` |
| Dataset | read-only; 11/11 manifest SHA-256 unchanged |

Feature selection, the 43-feature primary allow-list and the leakage guard are
imported from `scripts/train_baseline.py`, so the design matrix is identical to the
one both models were originally fitted on.

## 1. Global feature importance

> **These are model-based, associative explanations. They are NOT causal effects.**
> A coefficient says how the model used a column, not what would happen if you changed
> the real-world quantity. Channel, score and tier features are confounded by applicant
> mix, and this dataset records first-touch attribution, so no uplift or intervention
> claim is licensed by anything in this section.

### 2.3 Segment patterns worth carrying forward

Three patterns stand out in the tables above. They are observations about where these
two fitted models err, computed from the table rather than asserted.

1. **The forest abstains entirely on some segments.** It predicts a positive for *zero*
   test applications in 2 of the 29 non-small segment levels (`programme_id`=`PGM-05`, `academic_score_band`=`lt_60`).
   For those levels its false-negative rate is 100% by construction, so as a triage
   or outreach-prioritisation tool it would surface nobody in them at all. The
   logistic regression does flag applicants in every segment.
2. **Even where the forest does predict, its worst segment is `programme_id`=`PGM-02`**
   (n=523, positive rate 12.6%), where it misses 98.5% of actual
   enrolments against 84.8% for the logistic regression. Segments
   where enrolment is uncommon are exactly where a probability-compressed model is
   least useful, because it has no confident high scores to offer.
3. **Both models track the base rate across segments** - false-positive rate and
   positive rate move together in the same direction in every segment above, which is
   the expected behaviour of an unadjusted model. Neither has been allowed to
   over-predict anywhere, so neither is exploiting a segment-specific threshold.

### Why this matters if these probabilities feed forecasting

Every downstream consumer of a probability is implicitly assuming it means what it
says. Specifically:

- **Scenario arithmetic multiplies probabilities.** Converting an enrolment
  probability into an expected count, a seat-fill estimate or a funnel projection
  compounds any bias: a 10% relative error becomes 10% on every scenario output, and
  it does not cancel because the same model scores every row.
- **Over-confident probabilities overstate the upside.** A model that reports 0.90 for
  a marginal applicant makes that applicant look safe in a capacity plan when the true
  frequency is materially lower. That is exactly the failure that would quietly
  over-fill a seat plan.
- **Under-confident probabilities destroy discrimination downstream.** A compressed
  probability range means small but real differences between applicants get flattened,
  which matters if scenarios are ever ranked or thresholded rather than averaged.
- **Calibration drift compounds across cycles.** The enrolment base rate already falls
  across cycles (0.2923 train, 0.2661 validation, 0.2629 test). A model calibrated on
  training cycles will be progressively miscalibrated on later ones regardless of
  ranking quality.

This is recorded as a prerequisite for a later calibration step, not handled here.

## 4. Model comparison conclusion

Factual, on the existing test split, at threshold 0.50. Verified identical to the published figures.

| Question | Answer |
|---|---|
| Lower test log loss | **Logistic Regression** (0.4688 vs 0.4811) |
| Higher test ROC-AUC | **Logistic Regression** (0.7988 vs 0.7946) |
| Higher test PR-AUC | **Logistic Regression** (0.5473 vs 0.5450) |
| Higher test F1 | **Logistic Regression** (0.5318 vs 0.3627) |
| Higher test precision | **Random Forest** (0.5639 vs 0.5937) |
| Higher test recall | **Logistic Regression** (0.5032 vs 0.2611) |
| Better calibrated (slope nearer 1.0) | **Logistic Regression** (0.92 vs 1.67) |

**Precision / recall trade-off.** The forest is more precise and far less recall:
of the 347 applications it calls positive, 59.4% really enrol, against 56.4% for the logistic regression. In exchange it recovers only
26.1% of actual enrolments against 50.3%. This
is a high-precision / low-recall profile, and it follows directly from the calibration
difference in section 3 rather than from a different view of who enrols: at a matched
predicted-positive budget the two models score within ~0.01 F1 of each other.

**Calibration differences.** Logistic regression is mildly over-confident (slope
0.92); the forest is under-confident (slope 1.67), never predicting above 0.65.

> ### No universal winner is declared
> The logistic regression leads on every probability-quality and ranking metric measured
> on the test split, and it is better calibrated. The forest is more precise and would
> be a legitimate choice if false-positive cost dominated. But that is a preference
> about a downstream cost function, not a fact established by this data. **Model choice
> depends on the downstream use and the evaluation metric that matters for it**: a
> capacity planner weighting missed enrolments, a targeting workflow weighting wasted
> outreach, and a scenario engine needing well-calibrated probabilities would each
> justify a different answer, and none of them is settled by a single test cycle.

## 5. Limitations

1. **Synthetic data.** Every number describes a fit to a simulated funnel. Nothing here
   transfers to real institutional behaviour.
2. **Explanations are associational.** Coefficients and impurity importances describe
   model behaviour. They are not causal, and the dataset records first-touch
   attribution, so channel and source features are confounded by applicant mix.
3. **No local explanations.** This is a global artifact only. There is no per-applicant
   reason code, SHAP value or counterfactual, so an individual prediction cannot be
   defended to a specific applicant from this document.
4. **Single test cycle.** All error rates come from one held-out cycle of 3,001 rows with no confidence intervals, so small segment differences are
   not distinguishable from noise.
5. **Rows are not independent.** 2,529 applicants hold more than one application, so
   segment percentages are not independent samples. No resampling was done here; any
   future test must group by `applicant_id`.
6. **No calibration was fitted.** Both models remain miscalibrated, as section 3
   reports. This is deliberate and is a prerequisite for a later step.
7. **Selection bias in the population.** The modelling view is filtered to
   `stage_reached_order >= 3`, so all error rates describe applications that reached
   submission - not the top-of-funnel rate of 0.121.
