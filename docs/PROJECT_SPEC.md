# Project Specification

## 1. Project name

AdmitFlow v2

## 2. Academic topic

"Admission Conversion Forecasting with Funnel Attribution and Scenario Simulation"

## 3. Purpose

AdmitFlow is an analytics and decision-support platform for understanding admission funnel behaviour, forecasting future admissions and enrolments, comparing programmes and cohorts, and simulating controlled what-if scenarios with an explicit distinction between descriptive and causal language.

## 4. Problem statement

Higher education admissions teams need a way to understand where applicants are lost in the funnel, which segments underperform, and what outcomes are likely under alternative assumptions. The system should support both descriptive analytics and planning decisions without overstating causal certainty.

## 5. Scope

The project must include:

- synthetic admission dataset generation and validation
- funnel, cohort, and programme analytics
- attribution analysis with descriptive framing
- baseline and advanced ML models
- forecast generation for multiple horizons
- deterministic what-if simulation
- backend APIs and secure auth boundaries
- professional frontend analytics experience
- testing, evidence collection, and project tracking

## 6. Non-functional constraints

- code should remain readable and maintainable
- complexity should be appropriate for a final-year capstone project
- no fabricated metrics, screenshots, credentials, or completion claims
- all outputs must come from actual execution
- evidence must be stored and linked to task tracker entries

## 7. Required deliverables

- reproducible dataset generation workflow
- validation and profiling report
- analytics modules for funnel, cohort, attribution, and comparison
- ML model training pipeline with explainability
- forecasting pipeline with leakage checks
- scenario engine
- FastAPI backend with explicit API contracts
- React frontend with light/dark theme and analytics pages
- testing suite and evidence register
- final project report and verification documentation

## 8. Success definition

The project is successful only when a user can run the system, validate the data and models, inspect the dashboard, test the APIs, and review evidence showing the analysis was performed and verified in the current environment.
