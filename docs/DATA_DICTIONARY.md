# Data Dictionary

## Dataset profile

`data/admission_data.csv` is generated by `scripts/generate_dataset.py` using 4,200 rows and seed 42. The current validation report records 22 columns, no missing values, no duplicate applicant IDs, no invalid categories, and no invalid dates. The data is synthetic and does not represent real applicants.

| Field | Type | Description and domain |
|---|---|---|
| `applicant_id` | string | Synthetic unique identifier (`A00001` onward). |
| `cycle_year` | integer | Admission cycle, 2021 through 2026. |
| `application_date` | date string | Synthetic date in the applicant's cycle year. |
| `programme` | category | Data Science, Computer Science, Business Analytics, AI Engineering, or Applied Mathematics. |
| `selectivity` | category | Broad Access, Selective, or Highly Selective. |
| `region` | category | North, South, East, West, or Central. |
| `campaign_source` | category | Search, Referral, Social, Partner, Event, or Direct. |
| `campaign_code` | string | Source-prefixed synthetic campaign identifier. |
| `stage` | category | Exclusive final stage label: lead, application, submitted, review, admitted, or enrolled. Not a cumulative funnel count. |
| `academic_score` | decimal | Synthetic score, generated in the 0-100 domain. |
| `gpa` | decimal | Synthetic GPA, generated in the 2.1-4.0 range. |
| `engagement_score` | decimal | Synthetic score in the 0-100 domain. |
| `interest_score` | decimal | Synthetic score in the 0-100 domain. |
| `outreach_count` | integer | Synthetic outreach count from 0 through 11. |
| `campaign_clicks` | integer | Synthetic click count from 0 through 24. |
| `distance_km` | decimal | Synthetic distance, generated from 10 to 700 km. |
| `application_started` | binary integer | Cumulative flag: applicant started an application. |
| `submitted` | binary integer | Cumulative flag: application was submitted. |
| `review` | binary integer | Cumulative flag: application reached review. |
| `admitted` | binary integer | Offer/admission flag; includes enrolled applicants. |
| `enrolled` | binary integer | Target outcome flag; 1 for an enrolled applicant, otherwise 0. |
| `has_offer` | binary integer | Offer flag; generated equal to `admitted`. |

## Funnel interpretation

Funnel volume uses all rows as the lead population, followed by sums of `application_started`, `submitted`, `review`, `admitted`, and `enrolled`. These flags overlap by design. The `stage` field is a single final-stage label and must not be summed as though it were a cumulative funnel.

`admitted` and `has_offer` are currently duplicate indicators in the generator. They are retained as separate fields for clarity of downstream naming, not as independent information.
